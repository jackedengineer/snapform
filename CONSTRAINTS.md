# Quality and performance constraints

Established 28 October 2026 from the user's production, testing, native-first and performance requirements, plus the existing NFRs. Numeric first-slice budgets below are engineering defaults; measured evidence is recorded before changing them. The product is not production-ready until its release gates pass.

## Non-negotiable floor

- Do not add checker suppressions, skipped tests, fake implementations, silent catches or placeholder success paths to get green.
- Never remove meaningful assertions, weaken this contract or relax a threshold to hide a regression. Review such changes explicitly in a separate decision.
- No secrets in source; no customer data in fixtures; no raw answers/session credentials in logs.
- Generated route/runtime type files may contain tool-emitted directives. They are generated by pinned tools, not manually weakened; owned source is still checked strictly.
- Keep private endpoints fail-closed. A preview/validation endpoint must never claim it saved or delivered a response.

## Blocking checks for the implemented slice

| Dimension | Rule | Check |
|---|---|---|
| Formatting | Consistent formatting in new source/config, without generated-file edits | `pnpm format:check` |
| Types | Zero owned-source type errors; strict TS, no explicit any | `pnpm typecheck` |
| Lint | Zero configured errors or warnings in owned source | `pnpm lint` |
| Domain behavior | Focused tests must fail before new behavior and pass afterward | `pnpm test:unit` |
| Database identity | Real restricted Neon login, rollback-only synthetic writes, privilege/session checks; no second database | `pnpm test:db`, `pnpm test:auth:integration` |
| Boundary behavior | Actual workerd tests for expected/error/adversarial requests | `pnpm test:api` |
| Core coverage | At least 90% lines/functions/statements and 85% branches in implemented pure contracts | `pnpm test:unit --coverage` |
| Build | Web production build and API Worker dry-run bundle succeed | `pnpm build` |
| Route JS | Gzip entry + route/layout dependencies: home ≤125 KiB, collector ≤170 KiB, editor ≤190 KiB, inbox ≤175 KiB, other routes ≤200 KiB | `pnpm check:bundle` |
| Total web JS | At most 230 KiB gzip across all emitted client JS, including lazy routes; record largest chunks | `pnpm check:bundle` |
| Initial web CSS | At most 20 KiB gzip across emitted client CSS | `pnpm check:bundle` |
| Primary font | Latin variable font at most 40 KiB; optional Extended subset recorded separately | `pnpm check:bundle` |
| Dependency risk | No unresolved high/critical production dependency audit result | `pnpm audit --prod --audit-level high` |
| Git hygiene | No whitespace errors, secrets/env/build outputs; focused commits | `git diff --check`, staged diff review and `.gitignore` |

Coverage is scoped to the pure core, not presented as total-product coverage. Worker behavior is checked through its runtime; browser evidence is separate. Do not invent an arbitrary coverage badge for unimplemented features.

The user explicitly approved these route and total-JS limits on 29 October 2026
before the remaining V1 screens were implemented. They replace the first-slice
200 KiB whole-app JS limit through a separate recorded decision, [ADR-022](docs/decisions/ADR-022-route-performance-budgets.md).
The checker includes transitive imports, account layouts and non-route dynamic
features; it defers only other known routes. Missing/ambiguous modules fail closed.
CSS/font, coverage, correctness and security requirements are unchanged. These
artifact checks do not replace the production performance targets below.

## Every feature's browser gate

Run against the real local/staging application using synthetic data:

1. Normal user: discover, complete, correct and finish the intended journey; inspect loading/error/empty/focus states.
2. Power user: keyboard navigation, back/forward, rapid/repeated actions, zero/long/boundary values, refresh and relevant recovery.
3. Adversarial user: bypass client validation through an owned request boundary; malformed/oversized input, unknown keys/IDs, injection strings, forged permissions/signatures and duplicate/stale actions where those capabilities exist.

Record viewports and actual results. Check the console, document reflow, focus and data exposure. Use automated accessibility checks plus manual keyboard testing; screen-reader/real-device claims require actual runs. Keep tests bounded to owned environments.

## Measured release targets

The existing NFRs remain targets: standard form p95 usable at most 2s on the agreed mobile profile; INP p75 at most 200ms; CLS p75 at most 0.1; durable-submit p95 at most 800ms at the stated load. Measure the real deployed database journey before claiming these. Local bundle size and browser navigation timing do not establish production SLOs.

## Dependency and simplicity gate

Document new direct packages in docs/dependencies.md. Distinguish browser runtime, Worker runtime and development-only tooling. Commit exact versions and pnpm lockfile. Prefer native APIs; do not install the whole TanStack ecosystem, UI kit, date/utility/animation library or SDK in anticipation of future work. Review transitive changes and the emitted artifact rather than package marketing sizes.

Fast checks run during editing. Full implemented-slice verification runs before handoff/commit; browser checks supplement it. CI has no blanket timeout exception to omit a required check. Remote branch protection and deployment credentials remain setup tasks until a remote exists.
