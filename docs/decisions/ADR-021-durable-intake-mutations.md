# ADR-021: Revisioned progress and atomic finalization

Accepted 29 October 2026. Keep one response-session row through collection and finalization. Its immutable version supplies the form snapshot; a finalized row stores canonical answers, computed ending and submission time. Do not copy answers into a second response table merely to change lifecycle state. Private inbox access and retention are subsequent bounded interfaces.

Each save/submit carries an operation UUID, expected revision and bounded raw answers. PostgreSQL stores a SHA-256 digest of canonical jsonb request content and an immutable operation receipt. The same operation/body returns its original revision even after newer operations; changed reuse or stale fresh writes conflict. Hashing jsonb avoids object-key-order retry differences. Receipts contain no answer copy. The trusted application repeats the shared evaluator before calling the command; the database enforces capability scope, serialization, revisions, lifecycle and quota. It does not duplicate the form DSL in SQL.

All mutations lock the creator's quota counter, publication and session in that order. Starts already take the quota counter before the publication. This prevents admissions and finalizations from overspending the same allowance. Expired reservations must reacquire capacity while the original trial is eligible. Valid reservations have their existing short completion grace after trial expiry, but saves cannot extend that grace indefinitely. Successful eligible saves renew to fifteen minutes, capped by the session's progress expiry. Finalization increments consumed usage once and changes the session state in the same transaction. Deleting a future response must not refund this independent usage counter.

The runtime's previous direct column-update grants are removed. Fixed-search-path security-definer commands, with PUBLIC execution revoked, perform the controlled writes. Final answers are immutable through the mutation command. A valid respondent capability can still read/retry its submitted receipt after unpublishing, within its original 24-hour credential lifetime; unpublishing continues to revoke collecting sessions.

This transaction does not yet enqueue external email/webhook side effects. A durable delivery outbox must be joined to finalization before those integrations are enabled. No email, webhook or billing-provider delivery is claimed by an accepted answer.
