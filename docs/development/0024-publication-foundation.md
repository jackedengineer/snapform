# Immutable publication foundation

29 October 2026. Two additive migrations created private version snapshots and a separate live pointer in the existing Neon database. The runtime has no version UPDATE/DELETE grants; RLS uses actual membership, and composite foreign keys prevent a pointer from selecting another form or tenant's version. Publication is inactive by default. No anonymous read permission, public route or second database was introduced.

The schema test first failed with the missing module. After reviewed migrations, actual restricted-login tests verified immutable-row permissions, viewer/forged-role denial, actor identity, tenant isolation and composite pointer ownership. All fixture writes rolled back. Existing editor data still loaded with its original title, two pages and three saved rules after migration.

Typed publish requests contain only a stable version UUID and exact expected draft revision. Unpublish requests compare the current version UUID. Contracts reject unknown definition properties, invalid revisions and implicit truthy live state; receipt metadata may correctly differ from a later current publication. Three new contract cases bring the unit suite to 155 passing cases, with unchanged passing pure-core coverage.

The repository tests first failed with the missing implementation. Publishing now takes the same draft-row lock used by autosave, checks the expected revision, compiles the saved definition, then inserts its immutable snapshot and updates the pointer in one transaction. The original version UUID is its operation identity. Retrying returns a receipt and current state without moving the pointer or reactivating it. New explicit publications receive sequential numbers and retain the public identity. Unpublishing compares the current version before deactivation and is idempotent for that version.

All 17 real database tests pass. They cover draft edits after publication, repeated requests, old receipts after a newer publication, retry after unpublishing, explicit republishing, stale unpublish, invalid drafts, stale revisions, missing forms, viewer denial, another actor's operation identity and global ID collision with another form. Invalid and unauthorized attempts leave no partial publication. These rollback-only tests prove transaction/lifecycle behavior; they do not claim a simultaneous same-form two-connection race or a public respondent journey. Those checks belong to the HTTP/collection slices.

Types, lint and formatting pass. No dependency was added. The authority is [ADR-017](../decisions/ADR-017-immutable-publication.md); it names the existing draft row as the shared lock. Private HTTP endpoints, publishing controls, public collection and the remaining market V1 are still being built. This backend foundation is not a published form or launch-readiness claim.
