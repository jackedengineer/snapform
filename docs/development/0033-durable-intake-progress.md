# Durable progress and one-time finalization

29 October 2026. Migration 0013 adds immutable mutation receipts and finalization metadata. The controlled database command saves bounded partial progress with optimistic revisions, deduplicates retries, rejects changed reuse and serializes quota admission with finalization. It renews/reacquires short reservations, canonicalizes final answers through the application evaluator and consumes one response allowance atomically. Direct runtime updates are revoked. Submitted receipt access survives unpublishing until the capability's original expiry.

The behavioral test first failed because the mutation implementation was absent. After implementation and the forward migration, all four intake-session cases pass against restricted Neon credentials with rollback-only fixtures. The new case verifies partial-input recovery, stable retry, changed-operation and stale-write conflicts, invalid-submit rejection, zero normalization, final-state immutability, one consumed allowance, historical save receipts and submit retry after unpublish. An existing assertion was strengthened from an invisible-row update to SQL permission denial because direct column-write grants are now absent.

All 26 database tests pass. The production build succeeds; client JS remains 188.99 KiB gzip, CSS 5.46 KiB and font 36.07 KiB. Types, lint and formatting pass. No second database, reset or new dependency was used. This is a database/repository slice; there is no exposed mutation route or browser collector yet. Reservation-expiry timing, concurrent HTTP mutations and complete normal/power/adversarial respondent browser journeys remain explicit upcoming checks. [ADR-021](../decisions/ADR-021-durable-intake-mutations.md) records the lock order, trust boundary and unfinished side-effect delivery integration.
