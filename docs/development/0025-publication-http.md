# Private publication HTTP boundary

29 October 2026. Verified workspace owners/editors can read publication state, publish an exact saved revision, and unpublish an expected version through `/api/v1/workspaces/:workspaceId/forms/:formId/publication` (GET/POST/DELETE). Request bodies are strict bounded JSON (16 KiB); raw definitions and caller identities are not accepted. Existing same-origin, verified-session, no-store, write-rate and sanitized-error boundaries apply. Dates and receipt/current-state metadata are validated against the shared contract before returning.

The new runtime suite first failed with the missing route module. All 44 actual Worker tests now pass, including exact UUID-scoped matching, authenticated resources, JSON/size enforcement for both mutations and foreign-origin rejection. Strict types, lint and formatting pass. Production web/API builds and SSR/CSP/service-binding checks pass. Client JavaScript remains 188.99 KiB gzip, CSS 5.46 KiB and font 36.07 KiB; API bundle is 716.75 KiB gzip. The upstream CSS sourcemap warning remains visible.

A bounded owned HTTP probe used the separate synthetic draft-recovery form, not the agency form. Two concurrent identical publish requests used separate actual Worker/database connections and returned the same version ID/number. The next explicit publication advanced by exactly one, proving the duplicate had not inserted a second snapshot. A retry after unpublishing stayed inactive; an old unpublish after republishing returned 409. Unknown body properties returned 422, a future draft revision 409, and an unsupported method 405.

A publish and draft save then ran concurrently with the same expected source revision. The observed result was 200/200: publication obtained the shared draft lock first and recorded the original source revision; the edit committed afterward. The probe restored the exact original definition using its current revision and deactivated its current publication. The three immutable synthetic versions remain as QA history. Its separate authentication session was cleaned up; no auth email was sent and no database fixture was deleted or reset.

The existing browser editor continued loading its title, two pages and three rules after the additive database migration. This slice provides a private HTTP lifecycle, not a publishing UI or public respondent journey. Anonymous resolution, intake, file-pipeline readiness and the remaining market V1 are still pending; do not treat active private test metadata as proof that a public form can collect responses.
