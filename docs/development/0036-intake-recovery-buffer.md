# Bounded respondent recovery and retry buffer

29 October 2026. A strict seven-day recovery record scopes the native capability, pinned session and immutable pending operation to one public form/session. Malformed, mismatched or expired copies are rejected. Native IndexedDB keeps at most ten active form copies; reads prune expired/corrupt entries, writes refuse a full store, and storage failures remain visible. After finalization, the stored copy contains only the credential/reference and expiry, not an answer archive. The credential is never put in a URL or operational log.

The small progress controller serializes local writes and server mutations, debounces saves, preserves typing behind an in-flight save and reuses a lost request's exact operation/body. A newer server revision blocks further writes and preserves the buffer. Rate-limited retries wait at least a minute. An uncertain submission stays frozen until its original receipt is confirmed; a definite validation rejection releases the operation and allows corrections to resume saving. Closing drains/persists work rather than allowing a late write to refill a cleared copy.

Seven behavioral tests cover malformed/expired/foreign recovery, lost-save retry plus later typing, retry delays, honest unavailable IndexedDB, uncertain finalization, corrected rejected submission and stale receipt preservation. Tests first failed on the missing modules. No fake database or dependency was added. These tests exercise controller contracts, not the browser's IndexedDB implementation. Real refresh, multi-tab ownership, storage failure and three-mode browser workflows remain the immediately following collector integration gate.
