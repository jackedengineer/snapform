# Respondent file uploads

Implements file questions under [ADR-024](../decisions/ADR-024-uploads-before-scanning.md): Pro only, ten allow-listed types, 25 MB per file, at most 3 per question, private R2, attachment-only downloads, no malware scanning yet. Nothing here is applied, deployed or created remotely.

**Flow.** The collector checks a picked file (type from extension and browser report, size, room), then sends it alone to `POST /api/v1/public/forms/:public/sessions/:session/questions/:question/files` with the session bearer, `Content-Type`, `Content-Length` and a percent-encoded `X-File-Name`. The Worker handles these routes before Express so the body streams to R2. Before storing anything it asks the database (`authorize_intake_file`) whether the session is collecting, the workspace has Pro uploads, the question is a file question of the pinned version and has room. While streaming it refuses bytes past the declared length, checks the signature, validates text and hashes with `crypto.DigestStream`. Office manifests are read back by range from R2 and inflated with `DecompressionStream` within 1 MiB. Any failure deletes the object. `record_intake_file` then inserts the row under a session lock, so concurrent uploads cannot pass the limit. The answer stores file ids; on submit `write_intake_session` refuses ids that the session did not upload to that question, and the API then drops unreferenced files in the background. `GET .../files` lists a session's files; `DELETE .../files/:file` removes one while collecting. Members use `GET /api/v1/workspaces/:w/forms/:f/responses/:r/files[/:file]`.

**Codes.** Upload: 401 `INTAKE_UNAVAILABLE` (no bearer), 411 `LENGTH_REQUIRED`, 413 `FILE_TOO_LARGE`, 415 `UNSUPPORTED_FILE_TYPE`, 422 `EMPTY_FILE`, `INVALID_FILE_NAME`, `FILE_TYPE_MISMATCH`, `FILE_QUESTION_UNAVAILABLE`, `INVALID_FILE`, 400 `UPLOAD_INCOMPLETE`, 403 `UPLOADS_UNAVAILABLE` (not Pro), 404 `INTAKE_UNAVAILABLE`, 409 `FILE_LIMIT_REACHED` or `INTAKE_ALREADY_SUBMITTED`, 503 `UPLOADS_UNAVAILABLE` (no bucket or database). Publishing a file question on Free: 409 `UPLOADS_REQUIRE_PRO`. Submitting a foreign or removed file: 422 `INVALID_INTAKE_ANSWERS` with `FILE_REFERENCE_INVALID`.

**Native APIs.** No dependency was added. Upload progress uses `XMLHttpRequest`, because `fetch` cannot report request progress; same-origin XHR sends the browser's cookies, which intake routes ignore. Workers `FixedLengthStream`, `DigestStream`, `DecompressionStream` and R2 range reads do the rest.

**Setup the user must do.** Create a private R2 bucket named `snapform-uploads` in the Workers account. Leave public access, `r2.dev` and custom domains off; no CORS rule is needed. Both `apps/api` and `apps/jobs` bind it as `UPLOADS`. Apply migration 0046 after the other branch's 0045 and rechain the 0046 snapshot's `prevId` to 0045's snapshot; check that 0045 does not also replace `write_intake_session`. Optionally add a lifecycle rule deleting objects older than 400 days as a backstop beyond the 365-day maximum retention.

**Verification.** Contract modules `uploads.ts` and `upload-checks.ts` are fully covered. Workerd tests cover the upload, list, remove and download routes against real local R2 with a database stub: wrong or missing capability, account cookie, cross-origin and cross-site requests, Free plan, wrong question, full question, oversized declared and streamed bodies, short bodies, spoofed MIME (PNG as PDF, SVG and HTML as images, binary as text), invalid UTF-8, fake and macro-enabled Office files, path traversal, bidi and Arabic names, unknown outcomes and record failures, with nothing left in R2. Jobs tests cover prefix deletion before finalizing, bounded pages, unsafe prefixes and storage failures. Rollback-only tests in `packages/database/test/uploads.test.ts` are pending until 0046 is applied. Miniflare's R2 shim prints uncaught stream errors for aborted puts; a bare aborted put reproduces them.

**Budgets.** Measured gzip against feat/launch-polish at 5b634df: collector 152.81 to 156.65 KiB (170), inbox 157.46 to 158.71 KiB (175), editor 178.47 to 178.44 KiB (190, not grown), home 122.45 to 122.55 KiB (125), all JS 225.91 to 230.11 KiB (250), CSS 14.41 to 14.62 KiB (20). The upload control is a lazy chunk loaded only for forms with a file question; the measured route totals include it.

**Browser checklist (not run).** The journey needs 0046 in the shared database, and local ports 5173 and 8787 belong to other work. After applying, with synthetic data:

- Normal: on Pro, add a file question, publish, upload a PDF and a phone photo, see progress, remove one, submit, then see name and size in the inbox, download as an attachment, export CSV with names and receive a webhook with metadata. On Free, the editor note and the 409 message link to Plan and billing.
- Power: keyboard only (input, Remove, Cancel), drag and drop, three files then a fourth, refresh mid-way and see names again, back and forward, embed mode, 320 to 1440 px, Arabic and long names, a 25 MB file on a slow network.
- Adversarial: rename an `.exe` to `.pdf`, an SVG to `.png`, a `.docm` to `.docx`; send a body larger than `Content-Length`; reuse another session's file id in a submission; delete another session's file; download as a non-member and with a cross-site link; downgrade to Free and upload.

**Limitations.** No malware scanning, quarantine or upload backups. Purge is disabled in production, so abandoned and deleted files stay until it is enabled. A failed object delete after a removal or a crashed upload leaves bytes under the session prefix until that session is purged. Uploads are not idempotent: a lost response is retried as a new file. DOCX, XLSX and PPTX from tools that use ZIP64 or non-standard part names are refused. The jobs-role functions `purge_file_prefix` and `webhook_delivery_files` are tested through stubs only.
